CS 499 / ENHANCEMENT TWO

Algorithms & Data Structures.

Enhancing fault tolerance, structured result handling, and reliability in the AI Coloring Book Generator.

Artifact Overview

The AI Coloring Book Generator is a project I began roughly three years ago and have continued to develop as my programming skills have grown.

The application generates AI-created coloring pages based on subjects supplied by the user. The larger project includes a Python backend, frontend interface, authentication, credit tracking, a saved image library, and database persistence.

For this enhancement, I focused on the generate_book() method, which processes multiple subjects while maintaining their original order.

Original Algorithm

The original generate_book() method processed subjects sequentially and returned one ordered list containing paths to successfully generated pages.

Although this approach was simple, it had an important limitation: an exception during generate_page() could interrupt the loop and prevent subsequent subjects from being processed.

The original result structure also did not preserve information about failed subjects or their error messages.

Enhanced Algorithm

I redesigned generate_book() to maintain two separate collections: successful_pages and failed_pages.

The successful_pages list stores Path objects for completed pages. The failed_pages list stores dictionaries containing the failed subject and corresponding error message.

Exception handling now occurs inside the processing loop. If one generation attempt fails, the application records the failure and continues processing the remaining subjects.

Enhanced Python Implementation

successful_pages = []
failed_pages = []

for index, subject in enumerate(subjects, start=1):
    filename = f"{index:02d}-{slugify(subject)}.png"

    try:
        path = self.generate_page(
            subject,
            style=style,
            filename=filename,
            size=size,
        )
        successful_pages.append(path)

    except Exception as error:
        failed_pages.append({
            "subject": subject,
            "error": str(error),
        })

return successful_pages, failed_pages

This code is taken from the central processing logic of my enhanced generator, with the surrounding method definition omitted.

Data Structures and Design Decisions

I used ordered lists because the application needs to preserve the sequence of successful page results.

Dictionaries provide a readable structure for associating each failed subject with its error information.

The method returns both collections as a tuple, allowing other components to access successful and failed results separately.

The enhanced implementation is more complex than the original single-list approach, but the additional structure provides greater reliability and more informative results.

Command-Line Interface Integration

Changing the return value of generate_book() also required changes to the command-line interface.

I updated the CLI to unpack both collections, display successfully generated page paths, and report failed subjects and their errors separately. 

successful_pages, failed_pages = generator.generate_book(
    all_subjects,
    style=style,
    size=size,
)

This demonstrated the importance of considering dependencies when modifying an existing application.

Automated Testing

I created an automated test using a MockGenerator that simulates successful and failed generation attempts without calling an external image-generation service.

The test processes three subjects: cat, fail, and dog. The second subject deliberately raises an exception.

Test Input

subjects = ["cat", "fail", "dog"]

successful_pages, failed_pages = (
    generator.generate_book(subjects)
)

Expected Results

successful_pages = [
    Path("01-cat.png"),
    Path("03-dog.png"),
]

failed_pages = [
    {
        "subject": "fail",
        "error": "Simulated generation failure",
    }
]

The test verifies that the third subject is processed even though the second subject fails. It also checks that the error information is preserved.

GitHub Actions and Continuous Integration

I configured a GitHub Actions workflow to run the algorithm test automatically.

The initial workflow run failed because the test-file path was incorrect. After examining the workflow output and correcting the path, the test passed.

This experience helped me understand how automated testing and continuous integration can support reliable software development.

Reflection and Lessons Learned

This enhancement taught me that improving an algorithm does not always mean making it faster.

In this case, the most meaningful improvement was fault tolerance. The application can now continue processing after an individual generation failure.

I also learned that failure information is valuable data that should be preserved rather than discarded.

One challenge was updating the CLI after changing the return structure of generate_book(). This reinforced the importance of considering how components depend on one another.

Writing a controlled failure test and debugging the GitHub Actions workflow strengthened my testing and troubleshooting skills.

Course Outcomes

This enhancement demonstrates my ability to design and evaluate computing solutions using algorithmic principles and appropriate data structures while considering design trade-offs.

It also demonstrates the use of computing techniques and development tools to deliver practical value through automated testing, error handling, and improved application reliability.
