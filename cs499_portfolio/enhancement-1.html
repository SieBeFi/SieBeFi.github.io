CS 499 / ENHANCEMENT ONE

Software Design & Engineering.

Exploring modular application architecture, reusable software components, authentication, payment integration, and responsible configuration management.

Artifact Overview

ColoringBooks.AI is a full-stack web application I developed in July 2026 as a personal programming project. It generates AI-powered coloring book illustrations from text prompts.

Users can register for an account, receive free generation credits, create coloring pages, and access their previously generated content through a personal library.

The application also incorporates credit tracking, account management, and Stripe payment integration for purchasing additional credits.

I selected this artifact because it demonstrates how different technologies and software components work together within a larger application.

Application Architecture

The application uses a React frontend and a Python FastAPI backend. Its components are separated according to their responsibilities.

Frontend

React provides the user interface for authentication, dashboard information, page generation, account management, and the saved image library.

Backend

FastAPI provides API endpoints for authentication, generation, billing, books, and library access.

Shared Generation Module

The application also contains a reusable Python image-generation module in the src directory. This module supports both the standalone command-line interface and the web application's generation functionality.

Original Engineering Strengths

Before the capstone enhancements, the application already demonstrated several software engineering concepts.

  • Modular routing separated application responsibilities.
  • JWT authentication supported protected API endpoints.
  • Credit management implemented business rules for image generation.
  • Stripe integration supported payment-related operations.
  • Shared generation code reduced duplication between interfaces.
  • Environment configuration supported external service keys and application settings.

These were existing characteristics of the artifact, rather than features newly introduced during this milestone.

Enhancement Focus

My Milestone Two work focused on maintaining and refining the existing application, particularly its backend configuration and API-key management.

The scope of these changes was relatively small. However, working within the existing architecture helped me better understand the benefits of separating software responsibilities.

Because configuration, routing, credit logic, and payment services were already organized into separate modules, I could examine individual components without restructuring the entire application.

This experience reinforced the importance of maintainability and designing software that can accommodate future changes.

Software Engineering Design Decisions

Separation of Concerns

Organizing authentication, billing, generation, and credit management into separate modules makes responsibilities easier to identify and maintain.

Reusable Components

The shared image-generation functionality demonstrates code reuse across the command-line and web interfaces.

Business Logic

The credit system represents application-specific rules. New accounts receive an initial credit allocation, and generating pages consumes available credits.

Third-Party Integration

Stripe integration demonstrates how an application can communicate with an external payment service while keeping payment-related logic in dedicated modules.

Security Considerations

Security was an important consideration when working with authentication, API credentials, and payment services.

The project uses JWT-based authentication and environment variables for sensitive configuration values.

During project packaging, I also needed to ensure that real API keys and local environment files were not included in the shared archive.

Although I did not complete a comprehensive security enhancement during Milestone Two, this work helped me recognize the need for stronger input validation, endpoint protection, and security testing.

Technical Challenges

One of the most challenging aspects of developing this application was learning several technologies simultaneously.

I worked with FastAPI, React, JWT authentication, Stripe payments, Python, Node.js, and environment configuration.

I used textbooks, online tutorials, and developer discussions to research unfamiliar concepts and troubleshoot problems.

Setting up the project required coordinating backend dependencies, frontend dependencies, configuration files, and external API keys.

I also encountered Git-related issues while working with local project directories, which gave me additional experience interpreting development tool errors.

Reflection and Lessons Learned

This milestone helped me recognize that effective software engineering involves more than writing code that produces the expected output.

Application organization, documentation, maintainability, configuration management, and security all influence the quality of a software solution.

My biggest lesson was understanding the practical value of separation of concerns. A modular application is easier to revisit, understand, and modify.

I also recognized that I could have planned more substantial enhancements earlier in the course. This experience helped me identify opportunities for continued improvement, especially in security and documentation.
